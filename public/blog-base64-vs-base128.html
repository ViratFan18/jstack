ENCODING · PRACTICAL GUIDE

Base64, Base64URL, and JStack Base128

Encoding changes how bytes are represented so they can be carried as text. It does not conceal data, prove who created it, or prevent tampering.

Base64 represents bytes as printable characters

For the UTF-8 bytes of the text hello, standard Base64 is aGVsbG8=. Decoding the value recovers those bytes, which can then be interpreted as UTF-8. Padding and the standard alphabet are part of this representation.

Base64 is not encryption: anyone can decode it. Do not use it to store or transport passwords, API keys, or private information as if they were protected. Use a cryptographic design with appropriate key management when confidentiality or integrity is required.

Base64URL is a related but distinct alphabet

JWT compact serialization uses Base64URL for its encoded header and payload. It substitutes URL-safe characters and commonly omits padding. A general standard-Base64 text decoder may not accept every Base64URL value as-is; a JWT decoder handles compact token structure and still does not verify the signature.

Keep the operation explicit: decode a JWT to inspect it, and use a verifier with expected policy and key to check its signature. Neither action alone authorizes a request.

JStack Base128 is a custom format

JStack Base128 packs UTF-8 bytes into seven-bit groups and maps those groups to Braille symbols from U+2801 through U+2880. This is a JStack-specific mapping, not a universal Base128 standard. Another implementation may use different rules and cannot be assumed to decode it.

The custom mapping is also not encryption or a security feature. Use the matching JStack Base128 converter for round-trips. For standard Base64 text, use the separate Base64 converter.

Choose the format your receiver expects

  • Use standard Base64 only when the protocol or API specifies standard Base64.
  • Use Base64URL where the format requires URL-safe Base64, such as compact JWT parts.
  • Use JStack Base128 only when both sides implement this exact custom mapping.
  • Use encryption, not encoding, when the requirement is confidentiality; separately authenticate data when integrity is required.
